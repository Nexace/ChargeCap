# ChargeCap

<img src="artwork/chargecap-128.png" width="80" alt="ChargeCap icon">

A small native macOS menu bar app for Apple's built-in battery charge limit.

Click the battery icon to open a frosted panel directly beneath it. The slider snaps to **80%, 85%, 90%, 95%, or 100%**. Releasing the slider saves the selection and reads the setting back from macOS. Arrow keys and accessibility actions adjust it in 5% steps. At 100%, the panel offers the real **Optimized Battery Charging** switch.

Settings opens Battery settings. Click outside, press Escape, or click the icon again to dismiss the panel. The selected limit is stored by macOS and continues to apply after ChargeCap quits.

## Performance

Normal macOS launch and the complete interaction test measured **10.126 MB kernel lifetime peak**, **8.406 MB before opening**, and **9.651 MB after use**. This includes mouse tracking, keyboard and accessibility actions, all five charge limits, the optimized switch, and repeated reopening. The accepted target is approximately 10.13 MB; it is a measured result on the tested Mac, not a permanent OS-enforced cap. See `Verification.log`.

The final normally launched app averaged **0.00027% of one CPU core over 20 seconds** (0.054 ms total CPU time), with **8.013 MB idle RAM** and an **8.717 MB startup lifetime peak**.

The app uses Objective-C and AppKit, with no bundled runtime, web view, network requests, privileged helper, or secondary application process. Ordinary operation has no polling timer: it sleeps between native events and reads battery state when the panel opens or a setting changes. Dragging previews the value locally and writes only on release. Process-local allocator settings reduce heap overhead. Each control draws into one small reusable native IOSurface at the display’s backing scale; ordinary use has no rendering timer or animation loop.

The panel uses native compositor blur with a translucent surface and highlight rim, with a native visual-effect fallback. Reduce Transparency uses an opaque background. `research/Renderer.md` records the graphics investigation. Application measurements include app-owned graphics allocations; shared WindowServer costs are separate.

## Build

Requires Apple Silicon, macOS 26.4 or newer, and Apple's command-line developer tools. The verified machine is a MacBook Air M5 running macOS 27.0.1.

```sh
./build.sh
./test.sh
open ChargeCap.app
```

The build generates the icon from native drawing code and signs the bundle locally. Its native icon resource includes crisp menu/Finder sizes up to 128 physical pixels to keep startup decoding small. The app has no Dock icon. macOS can manage automatic startup through System Settings → General → Login Items.

```sh
./ChargeCap.app/Contents/MacOS/ChargeCap --diagnose
```

`--diagnose` reads settings without changing them. `--profile` opens the panel for a read-only observation. `CHARGECAP_PROFILE_KEY=1` gives the slider focus; `CHARGECAP_PROFILE_CYCLES=1` exercises five reopenings. `--verify` temporarily changes the five limits and optimized charging, restores the recorded originals, and exits nonzero if functionality or the accepted 10.13 MB RAM target fails. Run live verification when no other battery utility is changing settings. Unit checks include an environment-specific private-framework capability assertion.

Memory uses decimal MB from `TASK_VM_INFO.phys_footprint`; the kernel's lifetime ledger peak includes transient allocations. No memory polling timer is needed. CPU can be measured separately on a normal running instance:

```sh
xcrun clang -Os -Wall -Wextra -Werror research/cpu-measure.c -o /tmp/chargecap-cpu
/tmp/chargecap-cpu PID 15
```

## Compatibility and verification

Charge writes validate the available options, guard the inspected arm64 method signatures, and check independent readback. Tests cover rejected writes, unavailable controls, native ABI mismatches, slider snapping, preview isolation, keyboard and accessibility actions, the conditional optimized switch, and restoration of the original settings.

Battery control uses private PowerUI interfaces; the backdrop also uses a private macOS API. OS updates or unsupported hardware can make either unavailable. Physical charging behavior, other Mac models, actual logout/login, and display transitions are separate from software readback checks and have not all been physically verified.

`Preview.png` and `Preview-100.png` show layout renders; they do not capture the live desktop blur. The icon is generated by `artwork/draw-icon.m`. Graphify's source graph and report are retained locally in `graphify-out/`, with all extracted relationships preserved. The graph maps Objective-C class, method, and import structure; static C helpers are checked in the source and tests.
